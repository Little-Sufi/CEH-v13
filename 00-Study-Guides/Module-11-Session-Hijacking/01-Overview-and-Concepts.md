# 01. Overview and Concepts — Session Hijacking

> [!INFO] 📌 **Module Scope & Core Objectives**
> Direct technical extraction from official CEH v13 Syllabus (Module 11). Covers Session Hijacking concepts across Application and Network layers, TCP Initial Sequence Number (ISN) prediction, Session Fixation, Cross-Site Scripting (XSS) cookie theft, SSL/TLS Stripping, ACK Storms, and session hardening standards (`HttpOnly`, `Secure`, `SameSite`, HSTS).

## 🧠 1. Fundamental Principles & Layered Taxonomies

### 1.1 Application-Level vs Network-Level Session Hijacking
Session hijacking involves taking over an authenticated user's active session without requiring their username or password.

#### 1. Application-Level Session Hijacking
Targets HTTP/HTTPS session tokens, session cookies, and URL session identifiers generated by web application servers post-authentication.
- **Vectors**: Cross-Site Scripting (XSS) Cookie Theft, Session Fixation, Session Sniffing over cleartext HTTP, Man-in-the-Browser (MitB).
- **Mitigation**: `HttpOnly`, `Secure`, `SameSite` cookie flags, post-login session regeneration.

#### 2. Network-Level Session Hijacking
Targets active transport and network layer protocols (TCP/UDP) by injecting malicious data packets into an established TCP sequence stream.
- **Vectors**: TCP Sequence Number Prediction (Blind Hijacking), RST Packet Injection, UDP Session Spoofing, IP Spoofing + ARP Poisoning.
- **Mitigation**: Network IPS, IPsec / TLS encryption, random TCP ISN generation in modern OS kernels.

> [!ABSTRACT] 🏛️ **📋 Comprehensive Session Hijacking Layer Comparison Matrix**

| Hijacking Layer | Primary Target Asset | Dominant Exploitation Vector | Target OS / Application Component | Primary Defensive Control |
| :--- | :--- | :--- | :--- | :--- |
| **Application Layer** | HTTP Session Cookies / JWT Tokens | XSS Cookie Theft, Session Fixation | Web Browser & Web App Server | `HttpOnly`, `Secure` flags, HSTS |
| **Network Layer** | Active TCP Socket Connection Stream | TCP Sequence Prediction, ARP Poisoning | OS TCP/IP Kernel Stack | TLS Encryption, IPsec, uRPF |

## ⚡ 2. TCP Sequence Mechanics & Session Fixation

### 2.1 TCP Sequence Number Prediction & Blind Hijacking
TCP relies on 32-bit Sequence Numbers (SEQ) and Acknowledgement Numbers (ACK) to maintain packet order and connection state.
- **Attack Mechanics**: If an attacker can predict the Initial Sequence Number (ISN) of a target host, they can inject spoofed TCP packets containing malicious commands (e.g., `echo "attacker ALL=(ALL) NOPASSWD: ALL" >> /etc/sudoers`) into an active connection stream without seeing host responses (Blind Hijacking).
- **ACK Storm Condition**: When an attacker injects data into an active TCP stream, the client and server sequence numbers become desynchronized. Both endpoints repeatedly transmit TCP ACK packets to correct the sequence, causing a network **ACK Storm**.

### 2.2 Session Fixation Mechanics
Session Fixation occurs when an attacker forces a victim to use a known session identifier (SID) before the victim authenticates.

```
[Attacker] ---> Sends link with SID=999 ---> [Victim]
                                                 |
[Victim]   ---> Logs in with SID=999    ---> [Web Server]
                                                 |
[Attacker] ---> Accesses app using SID=999 ---> [Victim Account]
```

> [!IMPORTANT] 🔄 **📋 Comprehensive Session Cookie Hardening Matrix**

| Cookie Flag | Security Protection Mechanism | Attack Mitigated | Browser Enforcement Behavior |
| :--- | :--- | :--- | :--- |
| **`HttpOnly`** | Blocks client-side JavaScript access (`document.cookie`) | XSS Cookie Theft | Hides cookie from DOM scripts |
| **`Secure`** | Forces cookie transmission strictly over HTTPS encrypted channels | Plaintext Sniffing / SSL Stripping | Drops cookie on HTTP requests |
| **`SameSite=Strict`** | Blocks cookie transmission in cross-site requests | Cross-Site Request Forgery (CSRF) | Suppresses cookie on cross-domain links |
